1. ROOT CAUSE ANALYSIS — FID UNIFORMITY PROBLEM
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Previous session: All 6 sweep configs produced FID ≈ 439 with no hyperparameter sensitivity.

Diagnosed causes (Step 1 audit):
  • PRIMARY: N=256 FID has 30–80 point Monte Carlo variance. Config differences < noise floor.
  • SECONDARY: 1 epoch / 2000 samples = 31 gradient steps — control policy barely moves from zero.
  • SECONDARY: Score model weight ratios vs random init ≈ 1.0 across all layers (barely trained).
  • CAT5: DDPM sqrt(1–alpha_bar_t) could produce NaN at t=0 (fixed).
  • CAT6: Hydra struct mode rejects unknown config keys without prior YAML declaration (fixed).

Fix strategy:
  • Use N≥2048 for all reported FID values.
  • Train ≥5 epochs on full dataset (60k FashionMNIST).
  • Use Google Cloud VM for GPU-accelerated runs.

    Root cause: 1 – alpha_bar_t can be slightly negative due to float rounding when
    alpha_bar → 1 at t=0 in VP-SDE schedule.
    Fix: clamp(min=1e-5) before every sqrt(1 – alpha_bar_t) call.

  CAT6: Hydra struct enforcement rejects new config keys
    Root cause: Hydra's struct mode is strict about unknown keys.
    Fix: Added dataset_subset_size, early_stop_patience, early_stop_min_delta to both
    controlled_mnist.yaml and controlled_cifar.yaml before adding to dataclass.
