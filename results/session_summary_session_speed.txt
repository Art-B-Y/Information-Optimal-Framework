PROBLEM STATEMENT
-----------------
Session Speed was triggered by a catastrophic training failure: an 8-day run crashed
without saving any results. Root-cause analysis revealed three compounding bottlenecks:

  1. num_workers=0 (default) — DataLoader ran single-threaded, starving the GPU.
  2. loss.item() called EVERY step — forced CPU-GPU sync on every batch boundary.
  3. mixed_precision=False (default) — all matmuls in FP32, no Tensor Core utilisation.

Combined, these turned a projected 10-hour run into an 8-day disaster.

FIXES APPLIED (Steps 1–5)
--------------------------
Step 1: Profiling
  - Identified the three root causes above via manual timing and GPU utilisation
    monitoring (nvidia-smi dmon).

Step 2: Speed bottleneck fixes (src/its/training/controlled_score_training.py)
  A. DataLoader parallelism:
     - num_workers: 0 → 4 (new default)
     - prefetch_factor=2, persistent_workers=True added conditionally (nw > 0)
     - pin_memory=True (was already set, now verified by test)
  B. Removed .item() from inner loop:
     - loss.item() was called every step → moved inside log_interval gate
     - Deferred sync: `_loss_for_log = loss.detach()` (no sync); `.item()` only at log
  C. Automatic Mixed Precision:
     - mixed_precision: False → True (new default for both score and controlled training)
     - GradScaler("cuda", enabled=...) wraps backward in score_training.py too
  D. (Reserved for max batch size search — find_max_batch_size.py utility created)
  E. zero_grad(set_to_none=True) — replaces zero_grad() in 3 locations

Step 3: Fault-tolerant checkpointing
  A. 30-min autosave daemon thread (_AutosaveThread):
     - Daemon thread signals every N minutes via threading.Event
     - Main loop polls at batch boundary — no threading races with model state
  B. Atomic checkpoint write (_save_autosave):
     - Writes to autosave.pt.tmp, then shutil.move → autosave.pt
     - A crash during write never corrupts the previous good checkpoint
  C. Resume from autosave:
     - _resolve_resume_path checks autosave.pt before controlled_epoch_*.pt
     - global_step restored correctly; training continues from exact position
  D. JSONL writer: persistent buffered file handle (open once, flush at log boundary)
  D. Checkpoint pruning (scripts/prune_checkpoints.py):
     - Keep last 5 epoch checkpoints + every 10th before that
     - Always preserve controlled_last.pt, autosave.pt, score_best.pt

Step 4: Session segmentation (scripts/launch_segmented_training.py)
  A. Launcher runs training subprocess in a loop
  B. Training exits cleanly with sys.exit(42) at max_wall_hours limit
  C. Launcher restarts from latest checkpoint on exit code 42
  D. Log stitching (scripts/stitch_logs.py): merges JSONL segments chronologically

Step 5: Hardware utilisation
  A. TF32: torch.backends.cuda.matmul.allow_tf32=True (new config field allow_tf32=True)
  B. Frozen score model uses torch.no_grad() context in inference paths
  C. (Memory efficiency) gradient accumulation support via grad_accum_steps field
  D. CUDAPrefetcher (src/its/utils/prefetch.py):
     - Secondary CUDA stream overlaps H2D transfer with GPU compute
     - Transparent CPU passthrough; handles nested tuple/list tensor structures
