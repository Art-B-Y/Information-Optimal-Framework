FINDING A — sigma_max=1.0 IS ~42x TOO SMALL (completes Phase 1 defect A2)
--------------------------------------------------------------------------------
  Phase 1 flagged that sigma_max=1.0 is invalid for a VE prior but could not quantify
  it without the GPU. Measured now on FashionMNIST:

    data range               : [-1.0000, 1.0000]   mean -0.4306   std 0.7016
    max pairwise L2 distance : 41.88   (over 4000 training images, dim=784)
    median pairwise distance : 22.85

  Song's Technique 1 sets sigma_max to the maximum pairwise distance, so that
  p_sigma_max is effectively data-independent and the N(0, sigma_max^2) initialisation
  is a valid prior. The configured sigma_max=1.0 is ~42x too small: at sigma=1.0 the
  perturbed distribution still retains almost all data structure, so initialising the
  sampler at N(0,1) does NOT sample the VE prior.

  ACTION: the Step 1 retrain uses sigma_max = 42.0 (and sigma_min = 0.01). The score
  model has never been trained above sigma=1.0, so this REQUIRES the retrain — it
  cannot be applied to any existing checkpoint.

FINDING B — THE MODEL'S PRECONDITIONING IS BADLY CONDITIONED [FIXED]
--------------------------------------------------------------------------------
  ScoreUNet.forward did:  h = x/sigma ; score = F(h)/sigma
  With the DSM target -eps/sigma on x = x0 + sigma*eps, the network input is
  x/sigma = x0/sigma + eps, which is DOMINATED by x0/sigma at small sigma. Measured
  input magnitude (sigma_data = 0.70):

      sigma     input scale     what the network must do
       0.01        70x          extract eps from a 70x-magnitude input
       0.05        14x          extract eps from a 14x-magnitude input
       0.20         3.6x        mixed
       1.00         1.2x        ~eps, fine
      42.00         1.0x        ~eps, fine

  A 70x dynamic range in input scale across sigma — and the low-sigma end is exactly
  where sample quality is decided. This is a plausible contributor to the poor
  pre-audit FIDs (DDPM 197 at NFE=200; a healthy FashionMNIST model reaches < 20)
  that is INDEPENDENT of the four Phase 1 defects.

  FIX: added ScoreUNetConfig.preconditioning ("legacy" default | "edm") implementing
  Karras et al. (2022):
      c_in   = 1/sqrt(s^2 + sd^2)     c_skip = sd^2/(s^2 + sd^2)
      c_out  = s*sd/sqrt(s^2 + sd^2)  D(x;s) = c_skip*x + c_out*F(c_in*x, log s /4)
      score  = (D(x;s) - x)/s^2
  which holds the network input at unit scale for EVERY sigma. The RETURNED quantity
  is still the score, so all downstream consumers (DSM target, VE sampler,
  score_to_eps) are unchanged. "legacy" is retained for archive reproduction.

  VERIFIED: with F forced to 0, D = c_skip*x and the score must reduce to the exact
  analytic Gaussian score -x/(sd^2 + s^2). It does, to 0.00e+00 relative error across
  four decades of sigma (0.002 -> 42.0).

  SUB-FINDING — CATASTROPHIC CANCELLATION [FIXED]: computing the score in the literal
  form (c_skip*x - x)/sigma^2 loses ~4 significant digits at small sigma, because
  c_skip -> 1 makes it a difference of near-equal floats which is then divided by
  sigma^2. Measured 2.959e-03 absolute error at sigma=0.01 in float32. Since
  c_skip - 1 = -sigma^2/(sigma^2 + sd^2) EXACTLY, the sigma^2 cancels analytically:
      score = -x/(sigma^2 + sd^2) + (c_out/sigma^2)*F
  Algebraically identical, numerically stable. After the fix: 0.00e+00 relative error
  at every sigma tested.

FINDING C — THE DSM OBJECTIVE IS UNWEIGHTED [FIXED]
--------------------------------------------------------------------------------
  score_training.py:248 computed  loss = mean((score - target)^2)  with
  target = -eps/sigma. That is UNWEIGHTED DSM. The target magnitude is 1/sigma, so
  the loss scale goes as 1/sigma^2:

      sigma     |target|      loss scale
       0.01       100.0         10000.0
       0.10        10.0           100.0
       1.00         1.0             1.0

  Over sigma in [0.01, 1.0] the loss at the small-sigma end is 1e4x larger than at the
  large end, so the gradient is dominated almost entirely by the smallest sigmas and
  the large-sigma regime -- where the reverse trajectory STARTS -- is barely learned.
  Extending to the corrected sigma_max=42 makes the ratio 1.7e7, i.e. the corrected
  sigma range CANNOT be trained with the unweighted objective.

  FIX: added ScoreTrainingConfig.dsm_weighting ("none" | "sigma_sq"). With
  lambda(sigma)=sigma^2 the objective becomes sigma^2*(score + eps/sigma)^2 =
  (sigma*score + eps)^2 -- equivalent to eps-prediction, O(1) at every sigma. This is
  the standard choice (Ho et al.; Song et al.; Karras et al.). The validation loss uses
  the same weighting, or the overfit_ratio would compare two different scales.
  A convention guard now RAISES if dsm_weighting="none" is used with a sigma range
  wider than 100x, so this cannot silently recur.

FINDING D — FID WAS COMPUTED ON INVERTED IMAGES [FIXED, non-fatal]
--------------------------------------------------------------------------------
  evaluator.py constructed FrechetInceptionDistance(normalize=True) but fed it uint8
  tensors. torchmetrics' update() does:
      imgs = (imgs * 255).byte() if self.normalize else imgs
  so a uint8 input is multiplied by 255 and WRAPS MOD 256, mapping pixel v -> (256-v):
      uint8 [0, 1, 100, 254, 255]  ->  [0, 255, 156, 2, 1]
  i.e. every image is inverted before reaching Inception.

  HONEST SCOPING: because the same transform is applied to BOTH real and fake images,
  FID remained a valid distributional distance. This is NOT why the pre-audit FIDs were
  ~326 -- that was sampler defect A1. But FID was computed in an inverted pixel space,
  so the project's numbers are not comparable to published FashionMNIST FIDs, which the
  paper requires. Measured on identical inputs: 18.92 (bug) vs 20.79 (correct).
  FIX: normalize=False for uint8 input. InceptionScore(normalize=True) is CORRECT and
  was left alone -- it is fed float [0,1].
